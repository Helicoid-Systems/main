# Computer-centered monitoring

The user explicitly rejected a room/class-based product and asked for a general monitoring system. Computers and direct access permissions form the core model. Remove required rooms, classes, seats, courses, lessons, teacher ownership, and participant membership from navigation, records, commands, and authorization. A school can still deploy the product using the same general computer inventory.

A monitoring session belongs to one operator and identifies its bounded computer scope. Assistance, screen sharing, attention, files, and machine actions use explicit computer IDs and operation permissions. The user confirmed optional simple groups, automatic previews when the authorized console opens, and the broader tools without classroom concepts. Groups cannot become a required hierarchy or substitute for endpoint authorization. This supersedes the earlier Start Lesson trigger.

The subsequent request to follow Veyon's management workflow adopts its computer inclusion, preview grid, and selected-or-displayed action pattern. It does not reinstate a class/lesson entity. Native details are in [ui.md](../ui.md); inspected upstream evidence is pinned in the [research ledger](../research-2026-10-09.md#veyon-source-review-computer-management). Multiple viewers/one controller, one-time manager approval, and server file storage are also confirmed.
